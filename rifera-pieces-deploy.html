RIFERA CURSOR PIECES — DEPLOY

Owner-only page. Deploy the Rifera Cursor Pieces NFT (RPIECE) on BNB Chain: 5 sequential pieces — Pointer, Ember, Verdant, Frost, Void — that build one First Cursor. Nothing here deploys or moves funds without your wallet confirmation. Do NOT deploy twice: one contract, one set of pieces.

$Cash math

  • 1 complete set = 0.008 BNB to the project wallet: piece 1 (Pointer) FREE, pieces 2–5 0.002 BNB each.
  • 100% of paid mint BNB goes straight to the owner in the same transaction. Nothing is kept in the contract (withdraw() exists only as a safety net for stuck dust).
  • Payment must be exact — underpayment and overpayment both revert. Always call nextMintQuote(wallet) first.
  • Max 5 pieces per wallet (one complete set, one of each, in order). No 6th mint, no duplicates.
  • Supply cap: 1,111 per piece (Pointer, Ember, Verdant, Frost, Void) — 5,555 total. A sold-out piece reverts new mints of that piece (PieceSoldOut); since every wallet starts at Pointer, once Pointer sells out no new wallet can start. Check remaining with mintedPerPiece(piece) / remainingPerPiece(piece).
  • Staking: a complete set (one of each piece) can be staked in RiferaCursorStake to share the BNB pool — 10% of the remaining pool is released per day, split evenly between staked sets. The pool is funded manually (fundPool, step 08) from mint proceeds — there is no automatic split from mint fees, and no owner withdraw of the pool: pool BNB only leaves via staker claims.

Single ERC721 contract, name Rifera Cursor Pieces, symbol RPIECE. Constructor argument is fixed and read-only:

  • Agent ID required for every mint — free or paid (same gate as RiferaFirstTake).
  • Sequential mint: Pointer (free) → Ember → Verdant → Frost → Void (0.002 BNB each).

07Deploy RiferaCursorStake Not deployed

Stake one complete set (Pointer + Ember + Verdant + Frost + Void) to share the BNB pool: 10% of the remaining pool is released per day, split evenly between staked sets. Deploying staking does NOT open mint and does NOT fund the pool — mint stays closed until you press Open Mint (step 03), and funding is a separate manual step (08).

  • Constructor: (rpiece, owner) — owner is the connected wallet. The owner has no privileged functions over the pool or anyone's NFTs.
  • Staking needs a complete set held by one wallet; the 5 NFTs move into the staking contract and return in full on unstake.
  • Rewards only accrue while at least one set is staked. With zero stakers the pool stays whole.

08Fund the pool (manual, optional)

Send BNB into the staking pool with fundPool(). Anyone can fund — the owner is expected to fund it from mint proceeds. There is no automatic split from mint fees. Pool BNB can only leave through staker claims; there is no owner withdraw.

Deploy the staking contract first.

09After deploy

  • Verify the contract on BscScan / Sourcify (solc 0.8.24, optimizer 200, evm cancun, constructor arg = Agent ID registry above). In this repo: ./verify.sh <PIECES_ADDRESS>
  • Verify the staking contract too (if deployed): ./verify.sh <PIECES_ADDRESS> 56 <STAKE_ADDRESS> <STAKE_OWNER> — constructor args are (rpiece, owner).
  • Put the deployed address into the Rifera Game web (artifact rifera-game): Pieces section, Marketplace Buy, and the agent prompt.
  • The old RiferaFirstTake NFT (0x0Cd348360109dd7f966B94a37Ff9BB0542b07Ec3, 7,620 takes) is a separate collection and stays as-is. Do not wire pieces to it.
  • No funding step, no claim pool, no LP pairing in this contract — paid mint BNB goes to the owner immediately.
  • Staking needs no mint-open to deploy or fund — but nobody can stake until they hold a complete set, which needs mint open (step 03), and rewards need a funded pool (step 08).
